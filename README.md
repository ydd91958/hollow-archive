# 三层 ARG 原型

一款原创 ARG 网页游戏。玩家不是"角色"，而是一个从招聘网站上的一条普通职位开始、
一路查到某个不该被看到的内部系统的调查者。

设定、机构、编号体系、人物、地点、事件、术语全部原创，不使用任何既有作品的专有名词。

---

## 运行

本机未安装 Node.js。先装：

```bash
winget install OpenJS.NodeJS.LTS
```

装好后重开终端，然后：

```bash
npm install
```

```bash
npm run dev
```

打开 http://localhost:5173 。类型检查：`npm run typecheck`。

## 三层结构

玩家**不会**一打开就看到内部系统。完整路径是：

```
/                     第一层 · 职引（招聘平台）        普通中文互联网产品
  └ /jobs/PM-ARCHIVE    项目资料管理员 · 华北水测
  └ /company/HBSC       公司主页 → 项目沿革里冒出一个 1987 年的项目
  └ /people/WEIYUN      韦昀 · 资料不完整 → 页面自己列出「资料来源」

/forum                第二层 · 北岭生活论坛            地方社区站
/proj                 第二层 · 北岭地区工程资料库      2009 年停更的事业单位站
/blog                 第二层 · 窗台上的胶卷            退休测量员的个人博客

/proj/YL-87-03/attach/YL-87-03-A17
                      入口：一条失效的附件链接 → 500 错误 → 移交会话
/sys                  第三层 · 空册（原有内网，视觉与 ARG 引擎均未改动）
```

三层各有独立的外壳组件、配色、字体与「域名」。切换由 `<html data-layer>` 驱动
（`useLayerTheme`），`index.css` 按 layer 换 body 底色与字体——所以第一层是白的，
第三层才是黑的。

### 第一层的三条发现路径

玩家不该靠遍历五十条职位找线索，而该像正常人一样读资讯、点进去、顺手看一眼职位。
三条路线最后都汇到同一个地方：

```
A  首页秋招专题 → /special/campus2026 →「相关职位」里的项目资料管理员
                                      ↘ 相关阅读《旧资料到底有多重要？》(2019-11-03，文中有「四十一分钟」)
B  首页搜索「资料管理」→ 项目资料管理员
C  热门企业 / 找公司 → 华北水测 → 项目沿革
                          ↓            ↓
                    /jobs/PM-ARCHIVE → /company/HBSC
                                            ↓
                              /company/HBSC/project/YL-87-03
                                （资料正在迁移 · 资料来源）
                                            ↓
                                   /proj/YL-87-03  ← 第二层
```

**核心职位为什么不显眼**：秋招专题的核心文章第四节先用行业数据把「在架 96 天、
个别超过一年」「平均投递 11 人」写成这一类岗位的常态，并且平台上同时挂着
知识管理专员、技术文档工程师、技术资料工程师（88 天）、档案数字化专员（137 天 / 8 投递）、
工程资料员五条同类岗位。于是「419 天 / 3 投递」落在一片同类数字里，
它的不协调要等玩家看到 1987 年那个项目之后才会回头生效。

### 第一层首页的信息架构

按真实中文招聘门户的密度组织，容器宽 1200px，14 个模块、约 5,900 字、
52 个职位链接、18 个企业链接：

```
顶栏（城市切换 / APP / 企业版）
主导航 + 二级导航条
大搜索框 + 推荐词
┌ 职位分类（12 类，悬浮二级面板）┬ banner 轮播 + 两个小运营位 ┬ 登录卡 / 平台数据 / 求职提醒 ┐
热门城市（18 城标签 + 数字）
急招职位（3 列网格块）
┌ 推荐职位（20 行密集列表）              ┬ 高薪职位榜（带序号排行）  ┐
│ 应届生·实习专区（换底色分区）          │ 热门企业（紧凑行）        │
│ 最新职位（网格块）                     │ 求职工具（2×3 小卡）      │
│ 名企推荐（企业卡网格）                 │ 职场资讯（榜单）          │
热门行业（16 格分栏，无卡片）
职场资讯（三栏列表）
免责声明 + 五列页脚 + 热搜 + 友链 + 备案
```

**同一屏里有七种不同的信息结构**：密集列表行、网格块、排行行、标签行、
分栏格、企业卡、纯文本列表——刻意不复用同一种卡片。

数据规模：51 个职位 / 22 家企业 / 16 个行业 / 18 个城市，
其中 46 个职位、21 家企业与主线毫无关系。

**第一层和第二层的玩家可见文案里不出现任何第三层术语**（空册、残响、监护等级、
编号体系等）。这条约束由一条 grep 守着，改内容时请保持。

## 技术架构

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 构建 | Vite 5 | `@/` 别名指向 `src/` |
| 框架 | React 18 + TypeScript（strict） | Block / Trace 等联合类型用 switch 穷尽检查 |
| 路由 | React Router 6 | 每一"站"是一个带 Shell 的嵌套路由 |
| 状态 | Zustand + persist | 两套：`useTrace`（跨站痕迹）与 `useSession`（第三层 ARG 进度） |
| 样式 | Tailwind CSS 3 | 各层的设计令牌都在 `tailwind.config.js`，组件类按层分区写在 `index.css` |

**数据与 UI 完全分离。** 加一份档案 / 一个职位 / 一个帖子 / 一篇博文 = 往对应
`data/` 目录加一个对象，不改任何组件。

## 跨站状态与信号

第一层和第二层的各个站点**彼此不知道对方存在**，只往同一张痕迹表里写"我被看过了"：

```ts
note('person:WEIYUN')   // 韦昀资料页
note('project:YL-87-03')// 工程资料库的项目页
note('well:17')         // 点开第十七号井的著录补充
note('post:1103')       // 博客「十一月三号」
note('reveal:BBS-DELETED')
```

`signals.ts` 再从这张表推导页面变化。目前三条：

| 信号 | 条件 | 页面变化 |
| --- | --- | --- |
| `SIG_RECOMMEND` | 看过韦昀 + 云岭项目 | 职引「你可能感兴趣」多出一条玩家从未搜过的职位：**历史项目资料整理员** |
| `SIG_SNAPSHOT` | 看过论坛核心帖 + 博客「十一月三号」 | 论坛出现「查看本帖历史版本」，被删的那条回复变得可读 |
| `SIG_ATTACHMENT` | 看过第十七号井 + 博客「关于一段录音」 + 读过被删回复 | 工程资料库的 `YL-87-03-A17` 由「链接失效」变成可点——那是第三层的门 |

网站从不承认这些变化和玩家有关。幽灵职位没有发布时间、没有招聘者，
JD 描述的正是玩家此刻在做的事——但它一句元叙事的话都不说。

## 第一、二章 · 剧透（开发者用）

<details>
<summary>展开</summary>

**表面**：华北水文测绘技术服务有限公司成立于 2006 年，是一家正经的水文勘察公司。

**真相**：它由北岭市水文地质工程勘察队改制而来，2013 年整编档案时把老单位
1962—1998 年的项目卷册连同人员名单整个导入了自己的数据库——所以一个 2006 年
成立的公司，项目沿革里挂着 1987 年的项目和一个叫韦昀的人。**所有矛盾都由这一件事解释。**

**云岭 YL-87-03**：1987.04—1988.06，状态终止，结题报告未提交。第十七号观测井
（井深 214 米）于 1987.11.06 封填，此后的观测数据"未随卷册移交"。

**三个信息源各给一块**：

- 论坛 · 匿名回复：那晚仪器停了「四十来分钟」，第二天记录本被收走
- 博客 ·「十一月三号」：博主坚持是 **41** 分钟（22:14—22:55），被要求按 40 填
- 博客 ·「关于一段录音」：**1988-06-02** 晚上录的那盘带子，他再没敢放第二遍
- 论坛 · 被删回复（署名"窗台"，与博客同一人）：把上述全部串起来，并直接点名附件编号
  `YL-87-03-A17` ——「你们谁能打开，我请他吃饭」

**跨层设计**：`41` 和 `1103` 正是第三层 vault 访问码 `V-411103` 的两半。
玩家在第二层就已经握着它们了，进内网之后才知道它们是干什么用的。
`1988-06-02` 则是第三层 `TX-88-0007` 的转录日期。

**刻意保留的互联网碎片感**（都能解释）：博客说四个人、资料库人员名单第四行姓名栏空白、
韦昀页面第四名成员"字段为空"——同一件事的三个不同记法。

</details>
